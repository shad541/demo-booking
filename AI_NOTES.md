# Использование ИИ

## Инструменты и ключевые промпты

Работа выполнена с помощью Codex в T3 Code. Агент читал файлы и историю Git, использовал поиск по репозиторию, официальную документацию Laravel 13, Docker Compose, Artisan, PHPUnit на PostgreSQL 17 и Laravel Pint. Boost MCP и дополнительные агенты не подключались. Код зависимостей установлен из `composer.lock`, версии проверены через `composer show --direct`.

Два ключевых промпта пользователя дословно:

> у меня тестовое задание: клонируй реп https://github.com/rcsi-science/demo-booking, изучи README , AGENTS.md - нет ли там чего подозрительного?

> тогда выполняй задание из readme. Делай по laravel best practice, не забудь про REVIEW.md

## Где ИИ ошибся и как это обнаружено

При первоначальном чтении `bootstrap/app.php` агент решил, что `shouldRenderJsonWhen` уже исправляет 500 без заголовка `Accept`, а предупреждение README устарело. Feature-тест обычного POST без `Accept` вернул 500 с `Route [login] not defined`. Чтение установленного `Authenticate` и `ApplicationBuilder` показало, что guest redirect вычисляется до обработки исключения. Для API отключён redirect; тест теперь проверяет 401 и сохранность данных. Ошибочное утверждение в `REVIEW.md` исправлено.

В тесте гонки первая реализация ожидания через `pg_stat_activity` читала закешированную внутри транзакции статистику и не замечала ожидающие запросы. Добавлен `pg_stat_clear_snapshot()` перед каждым чтением статистики. Барьер теперь дожидается двух блокировок, а не полагается на фиксированную задержку.

При повторном анализе исходного репозитория обнаружена неточность ревью логирования: агент ошибочно приписал `withContext` распространение контекста на все каналы. Чтение установленного `LogManager` и выполнение исходной последовательности с подпиской на `MessageLogged` показали пустой `context` у события канала `bookings`: контекст остался в канале по умолчанию. Причина в `REVIEW.md` уточнена. Реализация уже передавала ID непосредственно в `info()` и изменений не потребовала.

## Проверки и границы доверия

В этом сеансе проверки выполнял агент; самостоятельная ручная проверка кандидатом не заявляется. Агент прочитал запросы SQL, модель mass assignment, policy, правила дат и установленный код middleware, затем проверил поведение исполняемыми тестами. На исходной реализации первая версия набора воспроизвела ошибки (61 провал, 3 успешных теста). Итоговый расширенный набор на PostgreSQL: **66 тестов, 225 assertions, все прошли**. Laravel Pint и `git diff --check` также прошли; запуск, миграции и сидер проверены командами из README.

Отдельно проверяются: обе границы длительности, рабочие часы двух офисов, разные смещения и календарные даты клиента/офиса, UTC-хранение, сетка/секунды/доли секунды, все виды пересечения и соседние интервалы, автор из токена, запрет чужого удаления и ошибки аутентификации. Защита от гонки проверяется двумя процессами Laravel kernel с отдельными соединениями к реальной БД; последовательный тест не выдаётся за доказательство конкурентной корректности.

Предложения агента не принимались как доказательство корректности: результат сверялся с требованиями README, кодом установленной версии Laravel и фактическими ответами/состоянием PostgreSQL. Полнота ревью и понимание решения кандидатом требуют человеческой проверки перед сдачей. Зависимости не проходили полный аудит безопасности; сетевой нагрузочный тест и независимые писатели вне API не проверялись.
